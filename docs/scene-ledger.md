# 场账本（Scene Ledger）· 中切设计合同

> 2026-08-01 Yi 拍板「中切」。病根诊断：引擎有世界层（时钟/作息/压力/帧表）和回合层
> （beats），但没有「场」——一段连续虚构时间、固定参与者、一件正在进行的事。虚构的
> 连续性只活在上下文窗口里（隐式），世界系统全是显式状态机；两者打架显式必赢，漏出
> 三种怪相：①邀约进行中角色被作息强拉走（括号蒸发）②语义重演（汽水递三次、问过又
> 答过的问题换措辞再问）③连续长谈跨时段（晨→黄昏戏没交代）。狗笼首航实弹，见
> plan-render 记忆 2026-08-01 条。
>
> 家法对齐：结构先行（守卫在替不存在的抽象层背锅，打地鼠不收敛）；申报优先、关键词
> 兜底（mood 配方）；宁漏勿误杀；危机压过戏；灰度旗默认关、单剧本试点。

## 1. 状态形状（都挂在 run.state）

```jsonc
"scene_ledger": {               // 当前开着的场；null/缺省 = 无场
                                // (键名避开 state["scene"] — 那是场面分类器的地盘)
  "open": true,
  "loc": "loc_rooftop",         // 开场时的地点 id
  "cast": ["shin"],             // 场内角色 id（不含玩家；玩家永远在场）
  "opened": {"day": 3, "slot": "晨"},
  "activity": "天台喝汽水聊城寨",  // ≤20字，一句话（plan 申报，兜底=空）
  "spent": ["递汽水", "开瓶"],   // 本场已花掉的标志性动作，≤8字/条，FIFO 上限 10
  "ticks": 0                    // 场内吸收掉的时钟拨格数（让位规则 b 用）
},
"asked_log": [                  // 问答账：跨场携带，按天过期（day+2 清）
  {"q": "对城寨怎么看", "a": "有人情味", "day": 3}
]                               // FIFO 上限 12；a=null 表示问了还没答
```

设计要点：**两本账两个寿命**。动作账（spent）跟场走，收场即弃——「递汽水」出了这
场就无所谓；问答账（asked_log）跟天走——不然换个地方他又问一遍。

## 2. 开收场规则（全部确定性，零新增 LLM 调用）

开场（当回合落账时判定）：
- v1 只做一条：无场开着，且本回合玩家真发了言（say/do）并有引擎台词拍落地。
  （「到达即开场」推迟——到达后的第一次对话交换反正会开，少一个挂点少一处险。）

收场（满足其一，收旧场；若新处境满足开场条件立刻开新场）：
- 三通路任一移动成立（硬移动 / moved_to 声明 / self_go 确认片）；
- 场内角色全部走净（必须是**走了戏**的离场，见规则 a）；
- 玩家离开存档（leave）、睡觉/翌日等时间跳跃；
- 兜底：场龄超 24 拍强制收（防账本永生）。

cast 维护：场中有人新加入对话 → 并入 cast；有人走戏离场 → 移出。

## 3. 让位规则 a：作息离场必须走戏

**实现 = 现成的钉子机制**：开场时把 cast 钉在场址（`char_pins`）。钉子在
`char_position` 七级判定链里天然压过作息，又天然被 濒死/威胁/被掳 压过——
**危机泄压阀是位置链白送的**，被猎手追杀的角色照样能夺门而逃，不需要另写规则。
收场只拔本场自己钉的钉（`pins` 名单），约定钟点的钉不归场管；
`_drop_pins_on_leave` 按「值==旧地点」拔钉，玩家一走场钉自然解除。

注：本规则只管「计划性离场」（作息表说TA该去别处了）。角色因剧情自己走（渲染拍里
写了告别）不受限——那本来就是走戏。

## 4. 让位规则 b：时钟在场内不许悄悄穿越

场开着时 slot 拨格：
- ticks < 2：**推迟**拨格（场内时间凝滞），scene.ticks += 1；
- ticks ≥ 2（封顶泄压）：放行拨格——`_slot_narr` 的时段翻页旁白本身就是当着玩家
  的「交代」，渲染注入不另做（拨格发生在 P9、渲染已完成，注入只能等下回合，不值）。
- 收场时未消化的 ticks 一次性补拨（世界不欠账）。⚠️ 5c 块内不许由 `_sl_close`
  直接改 `state["clock"]`（尾部 `state["clock"]=clk` 会覆写）——skip 收场时欠账
  并进本次 steps 一起拨。real_time 剧本时钟不归戏管，从不推迟也从不欠账。

封顶=2 的理由：活世界心跳、离线温养、约定到期全挂在钟上，玩家聊五十回合世界不能
冻死。推迟只为遮住「一炷香的戏被拨过半天」的穿帮，不为改变世界节奏。

## 5. 账本怎么写：plan 申报优先，确定性兜底

plan_turn 工具新增三个**可选**字段（照 mood/伏笔申报的写法，省略空字段零成本）：
- `spent`：本拍花掉的标志性动作（≤8字，如「递汽水」）；没有就省略。
- `asked`：本拍向玩家抛出的问题（≤10字概括）；没有就省略。
- `answered`：玩家刚才的话回答了哪个此前的问题（≤10字，须与 asked_log 里的条目
  对得上）；没有就省略。

确定性兜底（申报缺位时）：
- asked：主答者台词拍以「？/吗。/呢。」收尾 → 取末句提炼 ≤12 字入账（a=null）；
- answered：asked_log 里有 a=null 的问题、且本回合玩家发了言 → 该问题 a=玩家输入
  前 12 字（最旧的未答条目先结）。
- spent 无兜底（动作提炼太糙，宁漏勿误杀）。

## 6. 账本怎么喂：渲染指令注入（≤3 行，缺省零成本）

场开着时，render 指令（与单拍 system 同源处）追加：
- spent 非空：「本场已经演过：递汽水、开瓶——这些动作已经发生，不许再演一遍。」
- asked_log 有已答条目：「你问过『对城寨怎么看』，TA答了『有人情味』——接住这个
  答案往前走，不许换措辞再问。」
- asked_log 有未答条目：「你问过『……』还没得到回答，可以追问但别重抛新钩子。」
- 金色瞬间的 prompt 同样带 spent 清单（卡面不复述已演动作，已另有钉死人称条款）。

外加一条军令进渲染合同（不分场，恒常）：「玩家已经回答过的问题，绝不许换措辞再问；
每拍结尾不必都用问题收——接住对方的话往前走比抛新钩子高级。」

## 7. 灰度与验收

- 旗：`tuning.scene_ledger`，默认 **0**；狗笼三层打开试点（Story+快照+在途 pinned）。
- 冒烟：smoke_stories 全绿是底线；新增 tests/test_scene_ledger.py 盖：开收场判定、
  作息豁免与危机泄压、时钟推迟/封顶/补拨、申报入账、兜底问答配对、注入行生成。
- 验收指标（试点一两天）：重演率（同动作/同问题重现）趋零；离场括号在场内出现次数
  =0；守卫开枪榜不升；回合时长不涨（全程零新增 LLM 调用）。
