## 零、先纠正三条审计错误（不纠正会导致排期错配）

| 原判 | 实测 | 影响 |
|---|---|---|
| 每回合 ¥0.8~0.9，20 分钟 ¥15~22，对标月卡倒挂 20 倍 | 生产主链路是 **deepseek-v4-pro/flash 不是 qwen-max**（metrics 10515 条实证）。约 **¥0.06/回合**，20 分钟约 ¥2.4，倍率约 1.4 | 成本不是生存威胁，C 类整体降级；危险的是**没有配额时这个 ¥0.06 可以被乘到任意大** |
| 玩家输入注入可顶开 gating/secrets | 门控在组装前已过滤，locked fragment 从不进 prompt。真正可撬的是 **affinity 通胀**（好感是内容解锁总闸） | A9 从"信息泄露"改判为"主货币通胀"，修法从转义改为统一信封 |
| ipface.py / voice_styles.json / cover.py 是死码 | ipface 有 3 个现役消费者；voice_styles 运行期零成本；cover 的 `ENABLED=False` 是干净断电开关，后台线程不起 | D 类"删代码"的收益远小于预期，改为**冻结与标注**，不做删除工程 |

另有两条比原判**更严重**：

1. **`SHARED_LIBRARY=False` 单改是假修**。生产 31 本剧本 owner 全是 `demo@linguisplay.app`，而 studio.html:133 与 play.html:1104 预填该账号明文密码。必须旗子、预填、前端判 mine 三处同改，外加 me.py:127 `set_visibility` 压根不读这个旗子。
2. **日检从未完整工作过**。cron 每天点火，但 `git archive` 剥掉 `+x` → rc=126 静默失败，哨兵照常盖章。且 `df` 那行 awk 被 ssh 单行改文件时带进转义错误，**磁盘监控从 07-08 至今打印的一直是空**。

## 一、总裁决

> **先关门 → 三条不可逆 → 装秤 → 开门放人 → 用真人行为决定还哪块债。**

零玩家阶段花 15~22 小时逐个端点加固一个公网服务，是在替不存在的流量买单。**2.5 小时的 ufw + nginx 上游 127.0.0.1，就能把 A1/A3/A6/A8/A10/A11 的暴露面按到接近零**，换来整个施工窗口。

债务准入判据，只有两条，两条都不满足就进 BUGS.md：

1. 它是否挡住我在试点期间**当天热修**一个挡住玩家的 bug？
2. 它是否防止**不可恢复**的损失？

排序不看严重度，看**可逆性**：钱可以再赚，169MB 手绘和被封的账号不能。

**铁律**：`rsync --delete`、schema 差分器对生产开 DDL、批量 `unlink` 这三件事，一律排在**两份异地副本（库 + 美术）都验证过之后**。

- **拆 runtime.py / runs.py / play.html**：真问题，但单人兼职是一个季度的活，且在测试地基未修前重构等于蒙眼开刀。规则改为**只在本次改到的函数里就地缩，不发起专门拆分工程**。正当时机是它第一次真正挡住一个必须做的修改。
- **E3/E4 测试基建**（20 处解析层零测试、111 个手搓桩）：伤的是未来迭代速度，不是这十个人的一周。
- **E6 日志体系**（21 处 except pass）：只在这六周实际改到的 except 块里补，不发起专项。
- **G5 好感黑箱 / G6 无硬结局**：形态级问题，需要真人告诉你"不会失去的关系没有重量"是否真的伤到体验。W6 回访直接问。

- **F16 musicgen 非商业许可 / F17 音色池**：只在开始收费那天才有法律后果，推到判决之后。
- **文档漂移修复**：只做零成本的那件（改到哪个文件顺手改那处坐标）。

## 四、成功判据

### 第一层 · W1 末，二元，任一条不达标就不进下一周

大厅可见剧本数 == 1；公网 8100 不可达；探针账号越权全 404；生图失败时头像字节不变；Windows 上有一份恢复演练成功的 db；`pytest` 相对 891/3 基线零新增失败。

### 第二层 · W4 末，漏斗

≥4/5 生人 3 分钟内打出第一句有效 say 并到第 5 拍；beat_3 / beat_10 / beat_30 在 metrics 里可查；存档列表 p95 < 800ms（真实 0.4~0.8Mbps 线路实测）；寒山连续 3 晚夜巡零红；故障注入三连 3/3 告警。

### 第三层 · W6 末，真人行为，决定去留

- 激活率 ≥8/10（注册并到第 10 拍）
- 三次以上会话者 ≥5 人
- **无催促自发回访者 ≥3 人**
- 中位会话拍数 ≥25、中位时长 ≥15 分钟
- 每 100 拍 👎 数 ≤5
- 全周零安全事故，单日账单从未超 ¥50
- ≥5 人能用自己的话说清这游戏是干什么的

### 最终判据，只有一条，不许事后放宽

> **自发回访者 < 3 人，无论其余指标多好看，判定为形态假设未被验证。**

达标 → 分支 A：继续投入，开始还 W3 挂账的债，讨论定价与备案后的收费路径。
未达标 → 分支 B：**停止一切基础设施投入**，回到形态问题（G5 好感黑箱、G6 无硬结局、内容密度），用 W6 收到的文字反馈重新设计核心循环。

## 五、每周仪式

1. 周一开工前：`git fetch` 并确认本地不落后（历史教训：Windows 本地曾脱 git 9 天）
2. 每次改动前：先写红的断言（superpowers 铁律，不许"先实现再补测"）
3. 每次部署前：`smoke_stories.py` + `smoke_client.js` 两道门都过
4. 每条"不做"当天进 BUGS.md，写清解冻条件
5. 周日晚：对着本文件的出关条件逐条打勾，没打勾的不许滚进下一周（滚进去就是 G9 复发）
