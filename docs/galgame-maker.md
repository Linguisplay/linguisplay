# Galgame 生成器（制作加速工具）· 施工蓝图 v1

> 定位：**帮助创作者加速制作 galgame 的工具**。输入一个故事（或一个想法，或什么都不想写），
> 产出一部可发布、可被他人游玩的手机竖屏 galgame。制作完成后是纯 galgame：
> 点击推进、关键时刻选择，**没有自由输入、没有 AI 对话**。
> 与现有两模式并列：🏖 沙盒（自由）/ 📖 主线剧本（AI 导演）/ 🎀 **galgame（编译播放）**。

## 0. 核心架构判断

点击推进必须零延迟 → **建造期整章编译，播放期纯翻页**。
一次 LLM 调用产出一章的拍序列（说话人/台词/表情标签/场景/BGM/进退场/选择点），
玩家点击只翻预编译数据。「计划/渲染」哲学的极限形态：建造全计划，播放零调用。

## 1. 输入三档（创作者给多少都能开工）

| 档 | 创作者给什么 | 流程 |
|---|---|---|
| **A 全文** | 完整故事文本（限长，超长按章切块） | 直接进识别 |
| **B 智能拓写** | 梗概/片段/开头 | AI 拓成章节大纲 → **创作者确认/改大纲** → 逐章拓写全文 |
| **C 问卷** | 什么都不写 | 调查问卷：题材（恋爱/悬疑/恐怖/奇幻…）、世界观一句话、主角性别与性格、可攻略角色数与类型、口味（甜/虐/黑深残）、结局数、篇幅、🔞开关 → 生成梗概 → 并入 B 流程 |

**大纲确认是强制环节**（B/C 档）：拓写跑偏整本报废，必须在大纲层把关。
默认篇幅规格：3~5 章 × 每章 40~60 拍，一周目 30~60 分钟，2~3 结局。

## 2. 识别拍（结构化解析）

一次调用产出：
- **角色表**：名字、外貌描述（供生图，要具体到发型/服装/年龄）、性格、戏份权重、是否可攻略
- **场景表**：名字、视觉描述（供生图）
- **主角确认**：AI 提名 → 创作者确认/改选（galgame 必须有「你」）
- **章节骨架**：每章一句话 + 关键时刻候选

## 3. 编译拍（编剧）

按章生成 VN 脚本，每拍：
`{speaker|旁白, text, expression(表情标签), scene_id, bgm(情绪), enter/exit(进退场), sfx?}`
- 文风：`style` 字段照用（问卷口味映射到 style 文案）
- **关键时刻**：编译器判定情感/抉择节点插选择（兜底：每 15~30 拍必有一个）
- **分支哲学 = 伪分支**：选择改数值（各攻略角色好感/flag），主线收敛，
  **真分歧只在结局**（数值阈值决定进哪个结局）——复用现有关系账本与结局图鉴思想
- 选择影响下一章编译输入（选过的事是事实）；分支段落就地收敛（一场景内 rejoin）
- **🔞 拍标记**：成人场景的拍带 `adult: true`

## 4. 美术拍

- **立绘（多表情、无背景）**：
  - 一致性方案 = **一图四格差分表**：同一张生成图里同一人物画 常态/喜/怒/哀 四格
    （720×1280 内 2×2），服务器裁切 → 同图保同脸；要更多情绪（惊/羞）补第二张，
    接受跨图轻微不一致
  - 无背景 = 生图后 **rembg 抠底**（开源抠图，CPU 可跑，接在现有串行生图队列后）→ 真透明 PNG
  - 存放 `/scene/gal/{work}/{cid}_{expr}.png`
- **背景**：每场景一张 **720×1280 竖构图**（手机原生），art_style 画风字段统一全本
- **封面 + 标题画面**：自动生成一张封面（主角立绘+标题字由前端叠加）——工具产出要像成品
- **🔞 场景美术规则**：成人拍**只有背景+文字框**，立绘退场；这些场景的背景用
  含蓄空镜提示词（房间/床帐/月光空镜），文字承担全部内容（现有 R18 笔法块骑进编译提示词）
  ——正面绕开生图审查（已三次实证 API 会拒人物级成人图）
- 生图失败恢复：manifest 记缺项，可重跑补齐（backfill 模式）

## 5. 建造体验

- 全流程异步（几分钟）：**建造进度页**——识别角色 ✓ → 立绘 3/8 → 第一章编译中…
- 渐进可玩：文本编译完即可开玩第一章，立绘未就位用剪影占位，好了自动亮
- **制作台（修订能力，加速工具的灵魂）**：
  - 每张立绘/背景可「重画」（限次）
  - 每章可「重编」（保持已确认大纲）
  - 拍文本可直接改字（脚本是数据，改字零成本）
  - 全本换画风（art_style 一键重刷，复用 --redo 管线）
- **配额**：beta 每用户 **1 本**；建造成功才计数，失败可续跑不扣；
  重画/重编限次（立绘每张 2 次、每章重编 2 次）防刷

## 6. 播放器

- **手机竖屏舞台**：9:16 居中，四周纯黑；真手机全屏；隐藏一切模拟层 UI（无目标条/威胁条）
- **标题画面**：封面 + 开始/继续/回忆册/结局图鉴（galgame 的仪式感）
- **点击任意处推进**（复用已建 VN 窗：对话框/名牌/打字机/自动播放/skip/回想）
- 立绘按 说话人+表情标签 切差分，场景淡入淡出，BGM 按情绪标签
- 选择 = 预编译选项，点击瞬时接续
- 存档 = 章号+拍游标+选择历史+数值（骑 Run 表，mode="gal"）；CG/结局解锁跨周目持久
- **没有任何输入框**。自由发挥 = 无。
- 🔞 拍：立绘退场、背景+文字框呈现；作品带 mature 标记走现有 18+ 门

## 7. 发布与游玩

- 制作完成 → 发布到 discover 新分区「🎀 玩家作品」；作品卡带封面/时长/结局数/🔞标
- 他人游玩不耗作者配额；游玩数展示
- 版权：UGC 用户自担（beta 条款），内容安全靠提示词级脱敏 + 生图 API 拒绝兜底

## 8. 数据模型

- Story 表扩展 `kind`（"story"|"sandbox"|"gal"）+ `gal` JSON 列
  （source/survey/outline/manifest/script per chapter/values/build_status）
  ——复用发布、discover、快照、封面机制
- Run 表照用：mode="gal"，state={chapter, beat, choices, values, cg_unlocked}

## 10. 分期（功能齐全 = 全部在册，按此顺序施工）

| 期 | 内容 | 验收 |
|---|---|---|
| **P0** | A 档管线（识别→章编译→差分表+抠底+竖屏背景）+ 手机框播放器（纯点击） | 贴短篇 → 几分钟后点着玩完第一章 |
| **P1** | 选择+数值伪分支+多结局 + 🔞规则 + 标题画面 + 建造进度页 | 一本 3 选择 2 结局的完整 galgame |
| **P2** | B 智能拓写 + C 问卷 + 大纲确认环节 | 一句话/问卷也能出本 |
| **P3** | 制作台修订（重画/重编/改字/换画风）+ 发布分区 + 配额 | 别人能玩你造的本 |

## 10.5 多视角（Yi 拍板，一等公民）

> 一周目只能玩主角；通关后解锁其他角色的视角线——同一个故事，从 TA 的位置重讲一遍。

- **铁律：主线是账本，视角线围着账本转。** 建造时从主角线抽出【正史事件时间轴】
  （谁在何时何地做了什么），所有视角线编译都以它为不可违背输入——视角线补的是
  TA 的内心、TA 的幕后（主角看不见的那段 TA 在干什么）、TA 对同场戏的另一种读法，
  **绝不改写已发生的事**（文与实不许分家跨线版）。
- **真相机器**：编译器被明确指示——主角线里可以刻意留暗（她那晚为什么不接电话），
  让答案在她的视角线里揭晓。悬疑/恋爱题材的多周目发动机。
- **成本模型**：视角线复用全部立绘/场景美术，只花文本编译 + 少量新场景图；
  视角线针对**正史主干**编译（伪分支收敛后的 canon spine），不针对单个玩家的选择史
  ——否则每个玩家都要单独编译一条线，成本爆炸。
- **制作台**：创作者勾选哪些角色开放视角线（默认主角必有；每条视角线可更短、
  1~2 结局）；视角线支持同主线一样的重编/改字。
- **解锁规则**（创作者可配，默认=通关主角线任意结局解锁全部已制作视角线）；
  进阶：特定结局/好感阈值解锁特定线。
- **UI**：标题画面加视角选择——未解锁的角色显示剪影+锁（收集欲）；既读/CG/结局图鉴
  按视角线分账。
- **数据**：gal.script 按 pov 分层 {pov_char_id: {chapters…}}；Run.state 加 pov；
  解锁状态入 story_meta（跨周目持久）。
- **问卷/拓写档**顺带问一句：要不要多视角、给谁开线。
- **收费钩子**：视角线加购（第 2 条起）天然是付费点。

## 11. 补遗（v1.1 查缺，按「不提前设计会返工」分级）

### 🔴 必须现在进架构的

- **配音（TTS）**：galgame 标配。编译式架构是它的天然盟友——**建造期预生成全部语音**
  （无实时压力，gen_audio.py 底子在）。要求：拍结构预留 `voice` 字段、角色表预留
  「音色」属性（建造时每角色选声线）。v1 可不做，但字段和角色属性**现在就留**。
- **CG 全屏插画**：galgame 的奖励货币是 CG，不只是立绘。编译器给关键拍标 `cg: true`
  （告白/高潮/结局，每章 ≤1），建造期生成全屏竖构图插画，播放时全屏展示并入 CG 图鉴
  （回忆册直接吃）。拍结构现在留 `cg` 字段。多人同框一致性差 → CG 优先单人/空镜构图。
- **既读与选择统计的数据地基**：拍要有稳定 id；玩家的 per-beat 已读记录（跨周目
  既读跳过 = VN 刚需）+ 每个选择点的选择记录（聚合成创作者看板的选择分布）。
  **id 与埋点现在定**，功能后做。
- **编译记忆与节奏规范（编剧合同条款）**：章 N 编译必须带「前情摘要+选择史」输入
  （不然跨章吃书）；拍长 ≤60 字、对话:旁白配比、每拍一个信息点、旁白人称统一
  （主角视角第二人称「你」）——写进编译器合同，不靠模型自觉。

### 🟡 应该有，按期塞

- **画风预设库**（P0）：写实/日漫/古风/暗黑…每预设一段调好的 art_style 文案，
  创作者点选不裸写；问卷档自动映射。
- **建造排队与并发**（P0 就会撞上）：生图是全局串行队列，多人建造要有队列位次显示
  「前面还有 2 本在画」；单用户同时只能建 1 本。
- **合规预检**（P1）：建造前对文本过一遍敏感段落标记——提前把会被生图拒的场景
  自动转「背景+文字框」模式，而不是建到一半开天窗（本周三次被拒的教训制度化）。
- **结局回收导航**（P2）：通关后提示「还有 1 个结局未解锁，从第 3 章的选择岔开」
  ——多周目的发动机；配合既读跳过才成立。
- **标题画面全家桶**（P1 已含，补细节）：继续（读档）、CG 图鉴、结局图鉴、
  制作人员名单（创作者署名+「由 LinguisPlay 生成」水印位）。
- **演出小件**（P2）：立绘入退场滑动/生气抖动、黑屏白闪转场、画面震动；
  拍结构留 `fx` 字段即可。
- **创作者数据看板**（P3）：游玩数/完读率/每个选择的分布百分比（橙光验证过创作者
  黏性靠这个）；数据来自上面的埋点。
- **作品版本管理**（P3）：发布=快照（机制现成）；再编辑不影响在玩的人。
- **PWA**（P3）：加主屏图标+全屏，手机产品形态的临门一脚。
